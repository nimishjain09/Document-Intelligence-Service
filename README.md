# Document Intelligence Service

> **Problem:** Enterprises spend excessive time manually reading and extracting
> information from large volumes of documents, slowing decisions and raising costs.
>
> **Solution:** A modular, production-grade service that automatically summarizes
> documents and answers questions about them using AI (Hugging Face models + RAG
> with a local LLM), with async processing, quantization, Docker deployment, and
> multiple interfaces — all running locally to preserve data privacy.

A production-grade Python service that ingests documents (PDF, TXT, DOCX),
generates concise summaries using Hugging Face models, and answers questions
about them using a local LLM with Retrieval-Augmented Generation (RAG).

## Features

- Multi-format ingestion (PDF, TXT, DOCX) via the Factory pattern
- Abstractive summarization using facebook/bart-large-cnn
- Document Q&A using RAG with a local Ollama LLM (llama3.2)
- Async concurrent processing with a semaphore and thread-safe model access
- Structured JSON logging with per-document correlation IDs
- Automatic chunk-size validation against model token limits
- Optional INT8 quantization for optimized CPU inference
- Three interfaces: CLI, FastAPI REST API, and Streamlit web UI
- Docker deployment support
- Full unit test suite (14 passing tests)

## Requirements

- Python 3.11
- uv (dependency manager)
- Ollama (for the Q&A generative LLM)
- Docker (optional, for containerized deployment)

## Installation

    uv sync
    ollama pull llama3.2

## Configuration (.env)

| Variable          | Default                 | Description                     |
|-------------------|-------------------------|---------------------------------|
| MODEL_NAME        | facebook/bart-large-cnn | Summarization model             |
| MAX_CONCURRENCY   | 4                       | Max documents processed at once |
| CHUNK_SIZE        | 4000                    | Max characters per chunk        |
| MAX_OUTPUT_TOKENS | 256                     | Max summary length in tokens    |
| LOG_LEVEL         | INFO                    | Logging level                   |
| QUANTIZE          | false                   | Enable INT8 quantization        |

## Models Used

| Model                                     | Purpose        |
|-------------------------------------------|----------------|
| facebook/bart-large-cnn                   | Summarization  |
| all-MiniLM-L6-v2                          | Embeddings     |
| distilbert-base-cased-distilled-squad     | Extractive QA  |
| llama3.2 (via Ollama)                     | Generative QA  |

## Usage: CLI

    uv run doc-summarizer path/to/document.txt
    uv run doc-summarizer docs --format json
    uv run doc-summarizer docs --output summaries --quiet

## Usage: REST API

    uv run uvicorn doc_summarizer.api:app --port 8000

Endpoints: GET /health, GET /docs, POST /summarize-one, POST /summarize

## Usage: Web UI (Streamlit)

    uv run streamlit run streamlit_app.py

Open [http://localhost:8501%20to%20upload%20documents,%20view%20summaries,%20and%20ask](http://localhost:8501%20to%20upload%20documents,%20view%20summaries,%20and%20ask)
questions. Ensure Ollama is running for the Q&A feature.

## Document Q&A (RAG)

The Q&A agent embeds the question, retrieves the most relevant chunks from a
FAISS vector index, and uses a local Ollama LLM (llama3.2) to generate a
grounded answer with self-rated confidence. It answers only from the document's
content to avoid hallucination.

## Quantization

    QUANTIZE=true uv run doc-summarizer docs/article.txt

INT8 dynamic quantization reduces model memory and can speed up CPU inference.
QNNPACK (ARM) or FBGEMM (x86) backend is selected automatically.

### Quantization Benchmark (single run)

|------------------|----------|---------------|-------------|

| Metric             | Value  |
|--------------------|--------|
| Model load time    | 5.33 s |
| Summarization time | 8.17 s |
| Compression ratio  | 0.141  |

Note: These are single-run latency and compression measurements on one document.
Answer and summary quality were assessed via manual spot-checks; no formal

Result files are saved in the results/ folder. Measurements are generated by:

- benchmark.py — quantization benchmark (FP32 vs INT8)
- measure_performance.py — summarization latency on a single document
- measure_qa.py — Q&A (RAG) latency and confidence

## Testing

    uv run pytest -v

Tests use a mock summarizer, running in under a second without loading real
models. Coverage includes chunking, the loader factory, the async orchestrator,
and the vector store.

## Docker Deployment

Build the image:

    docker build -t doc-summarizer .

Run the container:

    docker run -p 8000:8000 doc-summarizer

Run with quantization enabled (no rebuild needed):

    docker run -p 8000:8000 -e QUANTIZE=true doc-summarizer

Then access the API at [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## Design Patterns

- Factory: LoaderFactory selects the loader by file extension.
- Strategy: SummarizerStrategy allows swapping implementations.
- Singleton (cached): get_settings() returns a cached Settings instance.
- RAG: retrieval-augmented generation for the Q&A agent.
